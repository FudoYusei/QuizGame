单例
-----------------
单例模式是整个程序运行时有且只有唯一的一个实例的模式  
单例模式对应的是抽象出来全局唯一或者说共享的资源, 例如常见的游戏配置文件, 通常会使用一个单例类集成对于游戏配置文件的操作, 然后全局都可以调用单例进行操作.  

优点:  
1. 使用简单
2. 性能优秀

缺点:  
1. 因为使用简单, 所有容易被滥用, 全局都可以调用, 相当于全局都存在隐形的依赖关系  
2. 特别是牵涉到单例中带有数据. 数据如果在不同的场景中发生变化, 那么就极其容易引起错误, 并且很难理清引起这个数据状态的逻辑, 所以在不同场景中一直变化的数据不应该保存在单例中, 单例中的数据最好都是只读数据.   
3. 单例模式通常简单的使用静态类实现, 但是静态类无法保证自身的初始化顺序, 因此静态类中的依赖关系需要额外控制  


Unity中的单例 
--------------------  
单例有很多种实现形式, 最简单的 static 修饰的静态类, 优化了初始化和解耦的依赖注入方式  

Unity Engine 的 MonoBehaviour 实例的初始化都是 Engine 代码控制的, 我们在 C# 中无法控制. 这样反而有一个隐形的好处: 在继承 MonoBehaviour 类型后, 这个类的实例保证在 Scene 加载时一同初始化.  
举例来说, 我们常用的 Awake 和 Start 方法中可以调用 Scene 中所有的 GameObject, 因为它们都在加载 Scene 的时候完成了实例化.  

单例模式需要解决的问题:  
1. 单例对象的初始化顺序, 编译器不保证静态构造函数的执行顺序, 因此想要在静态构造函数中使用别的对象可能会产生各种问题.  
2. 单例对象的生命周期, 单例对象通常都是全局可调用, 因此生命周期基本都是全局生命周期.


> ##### TIP
> [Awake 和 Start 方法的区别](https://www.cnblogs.com/guxin/p/unity-difference-between-awake-and-start-function.html)
> Awake 方法必然在场景中所有 GameObject 实例化后才会调用, Awake 方法通常用来初始化自身变量, 或者设置对于其他对象的引用   
> 在 Scene 中的 GameObject 会在全部初始化完成后, 开始调用脚本中的 Awake 方法, 但是并不保证 Awak 的执行顺序, 在 Awake方法中使用 GameObject.FindObject 可以找到场景中所有 GameObject  
> 但是如果在运行时使用 Instantiate 顺序实例化两个 GameObject A 和 B, 实例化完成后会立即调用 Awake 和 OnEnable 方法, 在 A 的 Awake 方法中无法找到之后实例化的 B.  
> Start 方法, 此时所有对象已经完成自身变量初始化, 可以调用其他对象实例方法  
> Start 方法会在 GameObject 实例化后, Awake 方法执行后, Update 方法调用前, 统一执行, 运行时实例化也是一样.

Bootstrap Scene
-----------------  
引导场景, 作为游戏程序启动时第一个场景, 引导场景中都是游戏启动必需先加载好的 GameObject.   
各个 Manager 作为全局单例对象需要在启动时加载并且一直持续到游戏结束.  

#### SequenceManager
引导场景中有一个名为 SequenceManager, 顺序进行各个单例 Manager 的实例化, 注意这个顺序的含义.  
场景中的 GameObject 会跟随场景加载时实例化, 并且在场景中所有 GameObject 加载完毕后, 才开始调用 Awake 和 OnEnable 方法. 也就是说, 同一个场景中的 GameObject 可以视为同时加载完毕, 没有特定的顺序.  
<font color=#4cd137>而在运行时, SequenceManager 脚本中调用 Instantiate 来执行顺序初始化, Awake 和 OnEnable 方法的调用逻辑会有差异, 它会在每个单独的 Instantiate 方法调用完成 GameObject 的实例化后立即调用实例的 Awake 和 OnEnable 方法</font>  

这就导致了如果要在 Awake 方法中设置其他 GameObject 的引用会失败. 例如, GameObject.FindObjectWithType 来查找还没有实例化的 GameObject 会失败  

SequenceManager 持有所有 Manager 的 Prefab 引用, 并且按照顺序实例化这些 Manager  

生命周期
---------------  
单例对象意味着全局可用, 因此单例对象应该是随着程序启动就初始化, 直到程序结束才销毁  

#### DontDestroy
默认情况下, Unity 以 scene 为单位统一加载 GameObject, 同时在切换场景时也会统一卸载当前场景中的 GameObjects  

Unity 提供了 DontDestroy API 来标记 GameObject 不会因为 Scene 加载/卸载操作而被连同卸载  

新建一个 DontDestroyOnLoad 脚本, 并挂载在 SequenceManager 中, 代码如下:  

{% highlight csharp %}  
    /// <summary>
    /// MonoBehaviour to preserve objects on scene loads. This can be useful
    /// for manager-level objects that need to persist over multiple scenes.
    /// If used, the user is responsible for manual cleanup using Object.Destroy.
    /// </summary>
    public class DontDestroyOnLoad : MonoBehaviour
    {
        private void Start()
        {
            DontDestroyOnLoad(gameObject);
        }
    }
{% endhighlight %}  

#### SceneLoader
还有种能够让新场景加载时, 不销毁当前场景中的 GameObjects, 以添加的方式加载场景  

{% highlight csharp %}  
//  
// Summary:
//     Helper class to avoid paying the cost of runtime type lookups. This is also used
//     to abstract underlying type info in the runtime (e.g. RuntimeTypeHandle vs StaticTypeReg)
public class SceneLoader : MonoBehaviour
{
        // Methods

        // Load a scene non-additively
        public void LoadSceneByPath(string scenePath)
        {
            StartCoroutine(LoadScene(scenePath));
        }

        // Coroutine to unload the previous scene and then load a new scene by scene path string
        private IEnumerator LoadScene(string scenePath)
        {
            if (string.IsNullOrEmpty(scenePath))
            {
                Debug.LogWarning("SceneLoader: Invalid scene name");
                yield break;
            }
            Debug.Log("Loading scenePath: " + scenePath);
            yield return UnloadLastScene();
            yield return LoadAdditiveScene(scenePath);

        }
}
{% endhighlight %}
