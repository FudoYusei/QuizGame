UI实例
-----------------
使用一些 DEMO 来解释 UI Toolkit 内置的组件运行机制  

text-field
-------------
具有复杂功能的 UI 组件, 都是一个 Container 作为 root element, 内部多个不同的基础组件, 例如常见的文本框 TextField  

TextField 的结构是:  

``` mermaid
stateDiagram
    Root --> Label
    Root --> Input
```  

text-field-1 作为 root element, 它会具有特殊的 Attribute: Label 和 Value  
这两个 Attribute 会影响其内部构造, 例如, 将 Label 的值置为空, 那么 Label 子元素会被从 TextField 中剔除   
这种特殊的动态表现, 和 UI Element 类的实现相关, 可以编写脚本实现自定义控件, 并且实现想要的各种动态功能, 就是有点麻烦  

<font color=#fbc531>在 UI Builder 中观察 TextField 的结构, 会发现, 我们无法直接更改 Label 和 Input 这两个子元素的任何属性和样式, 它们本身处于灰色的禁用状态, 为什么会出现这种原因?  </font>  
个人猜测, 这两个子元素是脚本动态生成的, 它们相当于虚拟节点, 只能由脚本控制. 例如, 在 Root Element 中更改 Label 和 Value, 就可以看到子元素跟随动态变化  

### 子元素样式
虽然无法直接修改这些虚拟元素的属性和样式, 但是我们可以通过 USS 来影响它们的最终的渲染样式, 就像 web 端的 虚拟 DOM 和 CSS 一样.  

可以通过 USS selector 来选中子元素并修改子元素的样式.  
可以发现, 默认情况下, 文本框的宽度跟随输入的内容改变, 显然不符合常用的认知.  
因此, 我们需要通过 USS 来控制文本框的宽度为一个固定值, 这样内部内容的文字就不会影响文本框的宽度  

使用 USS selector 选中子元素 input, 注意这里更改 basis 而不是 width, 并且 <font color=#4cd137>需要关闭自动填充, 即修改 grow 值为0, 原本默认为1, 并且因为 grow 是子元素值, 看起来很不明显, 非常容易漏掉, 但是自动填充会导致长宽值无效</font>.
   

这里使用的 USS Selector 为: TextField #unity-text-input 意味着影响所有 TextField 类型元素下名为 unity-text-input 的子元素  



> ##### TIP
>
> flex-basis 结合 flex-shrink flex-grow 以及布局等因素来计算出最终的宽高
> 这也是 flex-basis 和 width height 的区别
